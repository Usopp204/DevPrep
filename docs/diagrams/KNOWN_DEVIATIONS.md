# Known deviations — sequence page vs class page

> **How to verify any claim on this page:** run `python docs/diagrams/rebuild_all.py`
> (exit 0 = all sixteen diagrams regenerate, pass all nine checks, and still carry their
> original sequence page). See [README.md](README.md) for the rest of the toolchain.

Every class page under `docs/diagrams/out/` was rebuilt from the source code
(see `class_specs/`, generated by `generate_class_diagram.py`). The sequence
pages were **not** touched — they are byte-identical to the originals, which
`rebuild_all.py` verifies against `sequence_baseline.json` on every run.

That means a few places where the sequence page is incomplete, or disagrees with
the code, are now visible. They are listed here so there is a prepared answer at
the defence. In every case below **the class page is the correct one**, because
it was derived from the code that actually ships.

| # | File | What the sequence page does | Why the class page is still right |
|---|---|---|---|
| 1 | `ConductInterviewQA.drawio` | **Contradiction.** The messages imply the answer is graded **synchronously** — the old class page even showed a `SessionService.ScheduleGrading(...)` that does not exist in the source. | The real dispatch is asynchronous: `SessionService.SendMessageAsync` builds a `GradingWorkItem` and calls `_gradingQueue.EnqueueAsync(...)` (`SessionService.cs:936-952`), which returns immediately. `GradingBackgroundService` drains the queue and only *then* calls EvaluationAPI. The class page shows `IGradingQueue` / `BoundedGradingQueue` / `GradingWorkItem`; the sequence page never draws the queue. **The class page is right; the sequence page overstates what happens inside the request.** |
| 2 | `EvaluateInterviewAnswer.drawio` | **Contradiction.** Message 2 reads `Build EvaluateAnswerPayload; Task.Run(...) [best-effort]`. | `Task.Run` is not how grading is dispatched any more — it is the bounded queue above. The message describes a superseded implementation. Same root cause as #1. |
| 3 | `VoiceInteraction.drawio` | **Omission.** The STT branch stops at WebClient (`J.2`–`J.6`); the InterviewAPI hop is never drawn. | `InterviewSessionController.SpeechToText` and `IAiServiceClient.TranscribeAsync` are real and are part of this use case (`InterviewSessionController.cs:674`). The class page shows them; the sequence page summarises that branch instead of drawing it. |
| 4 | `EnrollFaceBiometric.drawio`, `EnrollVoiceBiometric.drawio` | **Omission.** No message names `EmbeddingCodec`, `BiometricSimilarity` or `CreditConfig`. | All three are on the enrolment code path: `EmbeddingCodec` at `ProfileBiometricsService.cs:65,76,107,175,190`; `BiometricSimilarity.Cosine` at `:106,188`; `CreditConfig.BiometricEnrollmentBonusCredits` at `:145`. The sequence page compresses the embedding/threshold arithmetic into single steps. |
| 5 | `ValidateEntryGateStatus.drawio`, `GetVerificationChallenge.drawio` | **Nothing wrong** — noted only because it looks like an omission. | 6 | `VerifyVoiceAnswer.drawio` | **Nothing wrong** — noted because it looks like a copy/paste error. `IAiServiceClient.VerifyVoiceAsync` returns `AiFaceVerifyResponse`, a *Face*-named DTO. | That is genuinely the shipped contract: both modalities share one generic `/internal/biometrics/verify` response shape (`IAiServiceClient.cs`). Each diagram is scoped to one service (stated in its title), so each shows its own service's type. The implementation boxes carry the service in their label; the interface boxes do not, because the diagram title already fixes the scope. |
| 8 | `EvaluateInterviewAnswer.drawio` | **Sequence page edited** — the only one in the set. Cells `s-m47` and `s-m48` said `ScheduleGrading(...)` and `Task.Run(...) [best-effort]`. | Both described a dispatch that no longer exists. Corrected under a scoped exception to §6, approved by duyentq, to `_gradingQueue.EnqueueAsync(GradingWorkItem)` and `GradingBackgroundService drains the queue`. An attribute-level diff confirmed exactly two `value` attributes changed across all 251 cells — no lifeline, cell or coordinate moved. `sequence_baseline.json` records the old sha256 and the reason. |

## If the board asks "so which page do we trust?"

The class pages. They were regenerated from the source and every class and method
on them is checked to exist with a matching signature. The sequence pages predate
the grading-queue rework and were otherwise left untouched — #1 is the one place
where a sequence page still contradicts the code, because only `EvaluateInterviewAnswer`
(#8) had its two stale messages corrected.
